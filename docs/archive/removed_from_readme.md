## Prerequisites

- Python 3.11+
- Cerebras API key from https://cloud.cerebras.ai/
- For the full system: PostgreSQL (local or RDS), Gemini key, Tavily key, Twilio account

## Installation

```bash
git clone https://github.com/PratyushSowrirajan/deepblue-CMC-chatbot.git
cd deepblue-CMC-chatbot
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # Linux/Mac
pip install -r requirements.txt
```

## Running the server

```bash
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Server: http://localhost:8000, Swagger UI: http://localhost:8000/docs

With Docker: `docker-compose up --build`. The container needs a reachable `DATABASE_URL`.

## Configuration

Environment variables the code actually reads (names only, never commit values):

| Variable | Used by | Notes |
|---|---|---|
| `DATABASE_URL` | all `*_db.py` modules | PostgreSQL connection string. Tables are created at startup, so the database must exist and be reachable or the app will not start |
| `JWT_SECRET_KEY` | `app/auth/auth_config.py` | Has a weak hardcoded fallback, always set it |
| `CEREBRAS_API_KEY` | `config/settings.py`, report generation, image-needed check | |
| `CHATBOT_CEREBRAS_API_KEY` | `app/chatbot/chatbot_config.py` | Required: the app raises `ValueError` at import if missing |
| `RAG_CEREBRAS_API_KEY` | `rag_pipeline.py` | |
| `TAVILY_API_KEY` | `rag_pipeline.py` | |
| `CALL_FUNC_CEREBRAS_API_KEY`, `CALL_FUNC_CEREBRAS_MODEL` | `app/call_function` | Model defaults to `llama3.1-8b` |
| `GEMINI_API_KEY` | `app/vision_model/gemini_vision.py` | Model is `gemini-2.5-flash` |
| `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_PHONE_NUMBER`, `TWILIO_VERIFIED_CALLER_ID` | `app/call_function` | |
| `CORS_ALLOWED_ORIGINS` | `app/main.py` | Comma separated, default `*` |

Cerebras settings (original README): model `llama3.1-8b`, temperature 0.3, max tokens 1500, JSON response format.

## Key features explained (original long version)

### is_compulsory field
- `is_compulsory: true` means the user must answer every session (symptom-related)
- `is_compulsory: false` means the app can pre-fill it from the user profile (demographics, medical history)
- Compulsory: current ailment, onset and duration, severity and pattern, associated symptoms, pain location, and for female patients the pregnancy and cycle questions
- Non-compulsory: name, age, gender, medical history, medications, allergies, lifestyle

### Conditional questions
Female patients get 2 extra questions: pregnancy status and menstrual cycle status.

### Symptom detection and follow-ups
The chief complaint is matched against the decision tree. Original examples were fever, chest pain and headache. The generated tree now holds about 50 symptoms from past RAG runs.

### AI medical reports
Generated by Cerebras with a nested JSON structure matching the app UI, patient demographics, differential causes, advice, and a red/yellow/green urgency.

## Security notes

- Never commit `.env`
- Keep API keys confidential
- Use environment variables for all secrets (AWS Secrets Manager for ECS)
- Add rate limiting and authentication for production

Known gaps found when reviewing the code (not in the original README):
- `/debug/*` endpoints in `main.py` are unauthenticated
- `POST /api/twilio/make-call` is unauthenticated and Twilio webhook signatures are not validated
- `JWT_SECRET_KEY` has a hardcoded default, CORS defaults to `*`
- Session state (`sessions` dict, Twilio call history) is in process memory, so it does not work across several tasks without the DB restore path
- Each query opens a new psycopg2 connection (no pool)
- The RAG cache is a JSON file inside the container, lost on redeploy
- `generated_decision_tree.json` contains junk entries from testing (for example `jjj`) and duplicates (`earpain` and `ear_pain`)
